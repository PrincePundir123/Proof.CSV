THE PROBLEM

A plausible answer isn’t enough.

Small teams need useful answers from messy spreadsheets. Chat alone cannot establish that an analysis ran, that its files exist, or that its code stayed inside a safe boundary.

  • Manual spreadsheet analysis costs time.
  • Generated code can fail or behave unexpectedly.
  • Users need results they can inspect and download.

THE PRODUCT

Upload a CSV → Ask a question → Execute → Inspect and download
  • Charts, computed metrics, and cleaned files.

  • One visible repair attempt using the real error.
  • Artifact hashes and verified container cleanup.
03 / 06
THE ARCHITECTURE

Vultr runs the control loop.

Browser ↔ Node.js backend on Vultr VM ↔ Vultr Serverless Inference

Backend → Offline Docker sandbox → Files + logs → Verified report

Inference credentials remain in the backend. The sandbox receives only the CSV, code, and execution limit. It has no network, host mounts, or Docker socket.

04 / 06
THE CONTAINMENT MOMENT

Stop the loop. Destroy the workspace.

The Safety Lab runs an infinite loop with a 3-second allowance. The runner terminates it, the backend destroys the container, and an independent inspection verifies removal.

  • 256 MB memory · 0.5 CPU · 64 processes.
  • Nonroot execution · read-only root filesystem.
  • No network · no host mounts · no credentials.
  • A second test probes the isolation boundaries.
